# Curtailment and Dispatch Data Acquisition

**Status:** sent 2026-07-11 — awaiting response

## Objective

Obtain the existing machine-readable operational records needed to
measure generation curtailment in Nepal without mistaking aggregate
system generation, exports, or annual plant energy for curtailed energy.

## What Is Already Public

- The Transmission Directorate's daily operational-report archive supports
  an existing local parser for daily aggregate NEA, subsidiary, IPP,
  import, export, demand and peak fields.
- As checked on 10 July 2026, the Generation Directorate's public
  operational-report page says "Coming soon" and its homepage shows no
  monthly-generation records. Neither portal provides the plant-level
  availability, dispatch instruction, reason code or rejected MWh needed
  for a curtailment series.

The request below deliberately excludes fields already available from the
daily aggregate archive. It asks only for existing records that identify
available generation, accepted generation and the reason for any gap.

## Request Scope

Request the existing electronic records for BS fiscal years **2080/81**
and **2081/82**, in CSV or XLSX where held. If plant-level disclosure is
restricted, request the same fields by anonymised generator ID or by
plant/corridor cohort. Do not request NEA to create a new analysis.

3. The data dictionary, report template, code list, or operating
   procedure that defines the above fields and reason codes.
4. Any existing register showing the contractual or payment treatment of
   recorded curtailment events, including whether compensation or deemed
   generation was recorded, where held.

If any requested record is not held by NEA, please identify the office
or public body that holds it. If any field cannot be disclosed, please
provide the remaining fields and identify the specific record or legal
basis for withholding that field.

## Review Checklist Before Sending

- Confirm requester eligibility and any required identification under the
  applicable information-access procedure.
- Address the formal request to NEA's Information Officer; copy only the
  operational directorates that may help locate records.
- Preserve the sent request, acknowledgement, response, file hashes and
  any refusal or redaction notice in a dated acquisition log.
- Do not publish station-level data until source, coverage, aggregation,
  privacy and contractual-disclosure conditions are reviewed.

## Intended Repository Outputs After a Response

1. Preserve originals under `data/raw/` with a manifest and hashes.
2. Validate any machine-readable return against
   `data/curtailment-dispatch-schema.json`.
3. Publish a derived, source-linked table only after coverage and reason
   codes are reconciled.
4. Update [[stranded-generation]] with bounded observations, never a
   national estimate inferred from unrelated annual totals.
