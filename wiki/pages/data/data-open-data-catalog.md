# Open Data Catalog

## Summary

This page lists every dataset the wiki publishes for reuse: the hand-curated CSV registries in `data/`, the derived tables in `data/processed/tables/`, and the main GeoJSON map layers in `data/processed/maps/`. Each row gives the live row and column count, a freshness date, the wiki page that explains the data, a JSON Schema where one exists, and a direct download link. The machine-readable version is [dataset_catalog.json](../../../data/processed/tables/dataset_catalog.json).

The catalog only describes files. It does not add any new figures, and it makes no claims beyond what each dataset and its companion page already state.

## Method and Coverage

`scripts/build_dataset_catalog.py` reads a curated list of datasets (title, domain, companion page, summary) and measures each file on every run:

- **Rows** are CSV data rows parsed with a proper CSV reader (quoted multi-line fields count once), or GeoJSON feature counts.
- **Cols** are CSV header columns, or the union of GeoJSON property keys.
- **Last verified** is the latest ISO date in a `verified_on`, `last_verified_date`, `reviewed_on`, `last_updated` or `source_updated_on` column. Where a dataset has none, the companion page's `reviewed` date is used instead and the JSON records `last_verified_basis: companion page review date`.

`--check` mode fails the release gate if a CSV is added to `data/` without a catalog entry, or if the counts on this page drift from the files.

## How to Reuse and Cite

- **Cite the dataset and the primary source.** Each CSV carries `source_slug`, `source_url` and/or `source_locator` columns that point to the original NEA, DoED, ERC, ICIMOD or other public document. Cite that primary source for any figure, and cite the wiki file as the compilation, e.g. *TransparentGov Nepal Energy Wiki, `data/substation_specs.csv`, accessed YYYY-MM-DD*.
- **Check the precision columns.** Coordinates carry `coordinate_precision` tags (exact, place anchor, district centroid and so on). District-anchored points are display positions, not site boundaries.
- **Check status dates.** Delivery status columns describe what a source reported on its date (`status_as_of`, `as_of_fy`), not live operating state.
- **Licence.** The repository compilation is MIT-licensed. Upstream government and institutional documents keep their own terms.

## Provenance Boundary (Tier A vs. Tier B)

The wiki applies a two-tier grounding rule to every dataset:

| Tier | Applies to | Rule |
|---|---|---|
| **Tier A — strict primary source** | MW, MVA, GWh, tariffs, revenue, profit, coordinates, delivery status | Every value traces to a cited primary document or a precision-tagged geocode. Nothing is estimated or invented to fill a gap; missing values stay blank. |
| **Tier B — canonical lookup** | District ↔ province geography, Bikram Sambat ↔ AD date conversion, ecological belt by district | Filled from Nepal's standard 77-district / 7-province administrative lookup and calendar conversion, and tagged `canonical-lookup` where the dataset records a basis. |

## Limitations

- The catalog covers the curated and key derived datasets, not every intermediate build artefact or review queue in `data/processed/`.
- Several curation tables (capacity authority decisions, identity aliases, licence overrides) are pipeline inputs rather than reader-facing registries; they are listed for transparency.
- Row counts measure file size, not completeness. Field-level completeness for hydropower and solar specs is reported in [spec_completeness_report.md](../../../data/processed/tables/spec_completeness_report.md) and [solar_spec_completeness_report.md](../../../data/processed/tables/solar_spec_completeness_report.md).
