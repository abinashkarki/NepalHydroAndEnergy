# Quality Rubric

What each quality tier means per category. Use this to assess pages honestly and prevent over-polishing or under-building.

## Global Tiers

| Tier | Meaning | Audience |
|---|---|---|
| `record` | Registry-backed factual page. Preserves map coverage and registry facts. | Machines, map users, researchers checking raw data |
| `brief` | Readable, basic explanation, some sources. | General readers who need orientation |
| `analysis` | Strong explanation, system relevance, evidence, caveats. | Researchers, analysts, journalists |
| `flagship` | Polished, well-sourced, canonical page. | Anyone who needs the authoritative reference |

## Per-Category Expectations

### Sources

| Tier | Minimum |
|---|---|
| `record` | Exists as a slug + title. No content yet. |
| `brief` | Summary paragraph + 2-3 key findings. |
| `analysis` | Summary + key findings + relevance + limitations + used-by list. |
| `flagship` | All of the above, plus cross-referenced claims, method notes, and update history. |

### Entities

| Tier | Minimum |
|---|---|
| `record` | Spec table + lead sentence. Auto-stub standard. |
| `brief` | Spec table + 1-2 paragraphs of context + sources. |
| `analysis` | Spec table + narrative sections (engineering, output, financial, significance) + sources. |
| `flagship` | All of the above + limitations & controversies + linked figures + comprehensive sources. |

### Concepts

| Tier | Minimum |
|---|---|
| `record` | Not applicable — concepts should not be auto-stubs. |
| `brief` | What-it-is + why-it-matters-in-Nepal. 3 paragraphs minimum. |
| `analysis` | Summary + simple explanation + technical explanation + examples + related. |
| `flagship` | All of the above + common misunderstandings + cross-links to claims and syntheses. |

### Claims

| Tier | Minimum |
|---|---|
| `record` | Not applicable — claims require evidence. |
| `brief` | Claim statement + 1-2 evidence bullets + confidence. |
| `analysis` | Claim + evidence + confidence rationale + unresolved issues + boundary conditions + related. |
| `flagship` | All of the above + explicit counter-evidence + confidence update history + cross-claim links. |

### Data

| Tier | Minimum |
|---|---|
| `record` | Dataset exists, minimal description. |
| `brief` | Summary + what it shows + coverage notes. |
| `analysis` | Summary + tables/figures + method + caveats + linked data files + chart specs. |
| `flagship` | All of the above + reconciliation notes + known contradictions + update history. |

### Syntheses

| Tier | Minimum |
|---|---|
| `record` | Not applicable — syntheses require argument. |
| `brief` | Core argument in 2-3 paragraphs + links to supporting pages. |
| `analysis` | Summary + core argument + evidence trail + implications + open questions. |
| `flagship` | All of the above + reading paths + public framing lines + update history. |

### Interventions

| Tier | Minimum |
|---|---|
| `record` | Not applicable — interventions require theory of change. |
| `brief` | Intervention description + theory of change + current status. |
| `analysis` | All brief elements + what it unlocks + research gaps + political feasibility. |
| `flagship` | All of the above + quantified benefits + comparable cases + institutional reform notes. |

## Target Distribution

This is the ambition for the wiki, not a mandate to fix every page immediately.

| Tier | Target % of pages | Action |
|---|---|---|
| `flagship` | ~5% (~18 pages) | Top 18 most-read pages |
| `analysis` | ~15% (~54 pages) | Core arguments, key concepts, major entities |
| `brief` | ~30% (~107 pages) | Most concepts, mid-size entities, supporting claims |
| `record` | ~50% (~179 pages) | Auto-stubs, data layers, minor sources |

## Assessment Rule

When assessing a page, ask:
1. Does it meet the minimum for its declared tier? If not, either upgrade the content or downgrade the tier.
2. Is it trying to do more than one category's job? If so, split it.
3. Does every claim trace to a source? If not, flag it.
4. Is the purpose statement clear in the first 2-4 sentences? If not, add it.
